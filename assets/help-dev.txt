铸壳工具链（ForgeShell）· s2a —— 构建与开发帮助（--help-dev）
================================================================================
本档是开发者视角：怎么构建、怎么自检、改名字换文案要动哪里、踩过的坑。
使用者请先看 `s2a -h` / `s2a --help` / `s2a --help-full`。

【1】构建
--------------------------------------------------------------------------------
  make
      依赖：musl-gcc、ld、upx。
      产出：
        build/template.elf     运行时模板（静态 musl，代码段基址 0x100000）
        build/launcher.elf     产物外壳（easy / enc 两模式，88,184 字节）
        build/*.enc            四档 help 的密文（编译期由 tools/help-enc 加密）
        build/*_blob.o         qemu / ash / launcher / 模板 / 四档 help 的 ld 内嵌对象
                               （qemu、ash 只链进 s2a，不链进产物）
        bin/s2a                编译器本体（约 2.89MB）
        bin/s2a-s              同一份、strip 过（约 2.84MB）
  make test
      跑自检：发射器对 as、前端解析、端到端编译运行。
  make clean
      清掉 bin 与 build 下的中间件。

  资源大小（当前）：
      qemu  1,893,000   ash  94,816   外壳 88,184   模板 445,680
      help 四档密文（短 3.1KB / 常用 17.1KB / 完整 31.0KB / 开发 7.8KB，随正文变化）
      产物：普通 ≈450KB / -easy ≈183KB / --only-enc = 外壳 + 原文件 + 128

  帮助文本的构建链（重要）：assets/*.txt（仓库里可读、可编辑的纯 TXT）
      → tools/help-enc 用 AES-256-CTR 加密成 build/*.enc
      → ld -r -b binary 嵌成对象 → 链进 s2a。
  所以 **帮助正文不写在 C 源码里**，改文案只改 assets/*.txt 再 make 即可；
  改完应确认二进制里搜不到明文（strings -a bin/s2a | grep -c 铸壳工具链 应为 0）。

【2】自检与回归
--------------------------------------------------------------------------------
■ POSIX 符合性（308 条）
    cd tests/posix_conformance && sh run.sh && ../../bin/s2a -o t.elf all.sh && ./t.elf
  判读口径：先跑 `bash all.sh` 做基准，再跑产物，逐条比"期望/实得"；
  **两边都失败的是自检脚本自身写错，只有产物失败才是真缺口**。
  当前状态：套件共 308 条，产物与 bash 在 303 条上完全一致；余下 5 条是自检
  自身写错（两边都不过）——即 0 条"只有产物失败"。
■ 端到端
    bash tests/run_e2e.sh
  编译若干脚本并检查输出与退出码（echo/变量/算术/if/for/while/函数/管道/命令替换/
  参数展开/case/退出码）。
■ 指令级对拍（模拟器 vs 真机）
    tests/gen_isa_bulk.py 生成 382 条指令用例；逐条对比寄存器与内存。
    当前 381 条一致，唯一差异是 SIMD 单车道存储 st1 {…}[i], [xn]。
■ 压力测试（加密/加固路径）
    bash tests/stress_protection.sh
  覆盖 -P/-F 产物启动、批量编译耗时、--only-enc（含多层与口令）等路径。

【3】手工验收清单（发布前建议过一遍）
--------------------------------------------------------------------------------
  · 普通编译 → 跑通；-s strip → 跑通
  · s2a -r 产物 → 模拟器跑通；--emu-own → 缺指令时按 132 报错
  · -F --password → 口令对／错各一次（错的必须是 70）
  · s2a ash -c '…' 与 s2a qemu --version → 可用
    （注意：产物里没有 ash/qemu，别用 `./产物 ash …` 验收）
  · -easy → 跑通且参数透传正确
  · --only-enc（无口令 / 带口令）→ 跑通；带口令时不口令必须 70
  · 加密多层嵌套：同口令一次、不同口令按层给
  · 四档帮助（-h / --help / --help-full / --help-dev）都能打印且不是乱码
  · strings -a bin/s2a | grep -c 铸壳工具链 → 0（帮助与敏感文案不落明文）

【4】改名字、换文案
--------------------------------------------------------------------------------
  · 帮助四档 = assets/help-short.txt、help.txt、help-full.txt、help-dev.txt
    （纯 TXT → 编译时加密嵌入，改完 make 即可）
  · 版本号与版本行 = src/compiler/main.c 的 S2A_VERSION / S2A_AUTHOR
  · 许可证正文 = src/compiler/main.c 的 g_license_text
  · 项目名出现在四档 help 的标题行、-v 输出与 Makefile/源码注释里
  · 帮助档位映射 = main.c 的 print_help()/print_help_plain()（档位 0/1/2/3 与
    文件名标签 short/detail/full/dev 必须与 Makefile 里的 help-enc 标签一致）

【5】开发笔记：踩过的坑（都已修，列出来免得再踩）
--------------------------------------------------------------------------------
  · 程序头表必须在第一个 LOAD 段内（AT_PHDR 推导），否则加载即崩。
  · 可执行段不能带 bss；filesz/memsz 页对齐。
  · 函数实参的 argv 必须 NULL 结尾：内建里拿到的 argv 没有结尾，
    直接交给 execv 会越界多读一个参数（`command echo A B` 多打一个 A）。
  · 参数展开里 `$1` 这类位置参数不在变量表里，要单独取；
    `${#*}`/`${#@}` 要按 $* 拼接长度算。
  · 引号内的元字符与**引号内的展开结果**都不参与路径名展开（否则 "$v" 会 glob）。
  · 词法扫描器直接改 pos 时行进列要重算（否则按列号切源码会切错，
    `(( ))` 的原文切片就吃过这个亏）。
  · 语句列表要能把 break/continue 与 return 的"信号"传给外层
    （内层列表会消费标志，外层必须另看一个不会被消费的标记）。
  · 子进程要恢复 SIGINT/SIGQUIT 默认处置（shell 自己忽略，exec 前必须还原），
    否则 `sh -c 'kill -INT $$'` 收不到信号。
  · 子 shell 不继承父 EXIT trap，但子进程自己设的 EXIT trap 到它退出时要跑；
    子进程退出前必须 fflush，否则缓冲输出整段丢失。
  · 重定向栈要按"标记"回退（不能一律弹空整个栈），
    否则 while 循环里第一个内建命令会把外层 `< f` 撤掉（只读到第一行）。
  · 换 fd 前后都要 fflush：缓冲输出在 dup2 之后才落盘会写错目标、甚至丢数据。
  · 主进程绝不能 ptrace(PTRACE_TRACEME)：父进程不会处理 ptrace 事件，
    本进程会永远停在 ptrace_stop（"启动后 [1]+ Stopped"就是这么来的）。
  · KDF 参数（算法、迭代次数、盐来源）在**编译器、运行时模板、外壳**三处必须
    完全一致，否则产物解出来是垃圾（表现为"未找到该命令"加乱码）。
  · 加密层嵌套时外层不能吃掉所有 --password 参数：只吃第一个，并把口令导出成
    S2A_PASSWORD，内层才拿得到（否则内层永远解不开）。
  · 帮助文本加密器曾把 32 字节摘要写进 16 字节 nonce 缓冲区（栈溢出冲掉密钥），
    表现是帮助输出乱码 —— 缓冲区别省。
  · UPX 输出文件若已存在会「Packed 0 files」静默跳过，要先删目标。
  · 追加文件时不能用 "a" 模式流的 ftell 当基准偏移（要另开一份量大小）。
  · **绝不对"用户给的路径"无条件 chmod**：曾用 `s2a -o /dev/null` 丢产物只看 AST dump，
    chmod 落到宿主 `/dev/null`（容器 `/dev` 与宿主 `/dev` 是同一 inode）→ 被改成 0755 →
    Android `webview_zygote`（uid 非 root）打不开 `/dev/null` 而 SIGABRT，
    系统上所有依赖 WebView 的 App 全部起不来。现在设权限一律走
    `src/common/safeperm.h` 的 `s2a_set_perm()`（先 `stat` 判 `S_ISREG`，非普通文件一律跳过），
    并在输出路径不是普通文件时打一行提示。事故全过程见 docs/incident-devnull-20260919.md。
